# Sky Cabin: An Interactive 3D In-Flight Service Simulation Game using OpenGL

**Course:** Computer Graphics and OpenGL (Fundamentals of Computer Graphics)
**Type:** Group Mini Project (team of 4), CCA / Open-Ended Mini Project
**Reference books:** Hearn & Baker, *Computer Graphics with OpenGL* (3rd/4th ed.); Edward Angel, *Interactive Computer Graphics*

---

## 1. Problem Statement

Learning computer graphics from isolated programs (a line here, a rotating cube there) makes it hard to see how the concepts work together in a real application. Students need a single, interactive application that uses graphics primitives, attributes, 2D/3D transformations, clipping, projections, colour models, illumination, input devices, GUI design, and animation in one place.

This project designs and implements **Sky Cabin**, a real-time 3D game set inside an aircraft cabin. The player controls an air hostess who must serve passengers' requests (coffee, snacks, blanket, and so on) before their patience runs out. The game is built with the OpenGL API and demonstrates every unit of the syllabus in a working, visible application.

## 2. Vision

A simple, colourful, easy-to-play game with a cutaway view of an aircraft cabin, built only from basic OpenGL shapes (cubes, spheres, cylinders, quads, lines). The game must run smoothly on a normal lab computer, be easy for every team member to understand and explain, and make each syllabus concept clearly visible on screen (for example the Bresenham-drawn HUD, the clipped mini-map, the projection toggle, and the lit materials).

**Objectives**
1. Implement graphics primitives and attributes (points, lines, circles) using Bresenham's algorithms.
2. Apply 2D/3D geometric transformations, clipping (Cohen-Sutherland), and perspective/orthographic projections.
3. Apply colour models and illumination (ambient, diffuse, specular, Phong) with OpenGL lighting functions.
4. Build interactive input and a GUI using keyboard, mouse, menus, and a HUD.
5. Use OpenGL animation procedures (double buffering, timer callbacks) for smooth, time-based animation.

---

## 3. Game Overview (How it plays)

1. A passenger's **request bubble** (with an item icon and patience ring) appears above their seat.
2. The hostess walks (WASD) to the matching **station** (coffee, snacks, and so on) and presses **E** to pick up the item.
3. She walks to the passenger and presses **E** to serve.
4. Correct and fast service gives points; a passenger whose patience runs out gives a penalty.
5. When the flight timer ends, the player receives a **1 to 3 star rating**.

Camera: a fixed, angled top-down cutaway view of the cabin (no ceiling, near wall removed).

## 5. Tech Stack

| Layer | Choice | Reason |
|-------|--------|--------|
| Language | **C** (C99) | Matches the syllabus and the reference books (Hearn & Baker, Angel) |
| Graphics API | **OpenGL** (fixed-function pipeline, `GL/gl.h`, `GL/glu.h`) | Matches the syllabus: `glTranslatef`, `glRotatef`, `glLightfv`, `glMaterialfv` |
| Window, input, menu, timer | **GLUT / freeglut** (`GL/glut.h`) | Gives `glutCreateMenu`, `glutKeyboardFunc`, `glutMouseFunc`, `glutTimerFunc` (Units 4 and 5) |
| Compiler / IDE | GCC (MinGW on Windows) or Code::Blocks, plus a `Makefile` | Same build on every laptop |
| Sound (optional) | Windows `PlaySound` (`winmm`) | Only feature outside the syllabus; skip if the lab PC is not Windows |
| Version control | Git + GitHub | One repo, one branch per member |
| Modelling | None. Primitives only | `glutSolidCube`, `glutSolidSphere`, quads |

**Setup**
- **Windows:** install MinGW and freeglut, or use Code::Blocks with its GLUT package. Build with `gcc *.c -o skycabin -lfreeglut -lopengl32 -lglu32 -lwinmm -lm`.
- **Linux:** `sudo apt install freeglut3-dev`, then `gcc *.c -o skycabin -lglut -lGLU -lGL -lm`.
- **macOS:** `gcc *.c -o skycabin -framework OpenGL -framework GLUT -lm`.
- Test the build on all four laptops and the lab PC on day 1.

**C-specific tips**
- Each module has a `.h` header (function prototypes) and a `.c` file, so members can work separately.
- Use `structs` for the hostess, passengers, and game state; use fixed-size arrays (no dynamic memory needed).
- Get delta time from `glutGet(GLUT_ELAPSED_TIME)`.
- Draw text with `glutBitmapCharacter`.

## 6. Architecture

### 6.1 Main loop

```
glutMainLoop()
  ├─ timer callback (every ~16 ms): compute dt → update(dt) → glutPostRedisplay()
  ├─ display callback: clear → draw sky → set 3D camera → draw scene → switch to 2D → draw HUD → swap buffers
  ├─ keyboard / mouse / menu callbacks → change state or input
```

### 6.2 Game state machine

```
MENU ──Start──► PLAYING ◄──Resume── PAUSED
                  │  ▲                ▲
                  │  └───── Pause ────┘
                  ▼
              GAME_OVER ──Restart──► PLAYING
```

Each state decides what `update()` runs and what `draw()` shows.

### 6.3 Layers

| Layer | Modules | Responsibility |
|-------|---------|----------------|
| Application | `main.c`, `state.c`, `config.c` | Window, callbacks, state machine, constants |
| World / Scene | `cabin.c`, `sky.c` | Grid map, cabin, seats, stations, clouds, lighting |
| Actors | `hostess.c`, `passengers.c` | Player and NPC data, models, animation |
| Game logic | `flight.c`, `requests.c` | Timer, request spawning, patience, score, stars, turbulence |
| Presentation | `camera.c`, `hud.c`, `menus.c` | Camera and projection, 2D overlay, menus |
| Graphics algorithms | `primitives.c`, `clip.c` | Bresenham line and circle, Cohen-Sutherland |

### 6.4 Interface rule

Every module has a header with simple functions called by `main.c`, for example `void hostess_update(float dt);` and `void hostess_draw(void);`. This lets each member test their module alone.

### 6.5 Core data (C structs)

- **Grid:** a 2D `char` array, one character per tile (`W` wall, `.` floor, `S` seat, `C` coffee, `K` snacks, `L` lavatory, and so on).
- **Hostess:** `struct` with position, direction, held item (enum), walk phase.
- **Passenger:** `struct` with seat tile, state (enum: `IDLE`, `REQUESTING`, `SERVED`, `ANGRY`), requested item, patience. Kept in a fixed array.
- **Game:** `struct` with state (enum), score, combo, time left, level, difficulty.

All time-based movement uses `dt` (seconds since the last frame).

## 7. File Structure

```
sky_cabin/
├── Makefile         # one command build for everyone
├── main.c           # window setup, GLUT callbacks, main loop (one owner merges)

├── hud.h/.c         # text, score, timer, progress bar, bubbles, floating text, mini-map
├── primitives.h/.c  # bresenham_line(), bresenham_circle()
├── clip.h/.c        # cohen_sutherland()
├── menus.h/.c       # glutCreateMenu setup and menu callbacks
```
